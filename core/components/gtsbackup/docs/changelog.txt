gtsBackup 1.1.1-beta
- Клиенты ходят на сайт по HTTP/1.1: за nginx-прокси на Apache при HTTP/2 терялось тело ответа.
- Команда в окне токена — без --dest: бекапы в подпапке backups рядом с клиентом.

gtsBackup 1.1.0-beta
- Клиент для Windows на PowerShell (gtsbackup.ps1): ничего ставить не нужно — встроенные PowerShell 5.1,
  curl.exe, tar.exe; задача — Register-ScheduledTask. gtsbackup.php остаётся для Linux/macOS, конфиг и папки общие.
- Архив — POSIX pax: имена не из ASCII и длинные — в расширенном заголовке (UTF-8), русские имена правильно
  разворачивают tar.exe и 7-Zip. Клиенты читают и архивы 1.0 (GNU LongLink).
- ping.roots — список {prefix, path} (ключ '' не разбирает PowerShell 5.1).

gtsBackup 1.0.1-beta
- Клиент перенесён в пакет: core/components/gtsbackup/client/, описание протокола — core/components/gtsbackup/client/protocol.md.
- Клиент не выполняется через веб (только командная строка).
- Пакет не создаёт групп ресурсов; исключения по умолчанию без чужих компонентов.
- Клиент хранит бекапы цепочками: <время полного>/full и diff-<время> рядом; list — дерево и сводка.
- add сам ставит задачу «gtsBackup» от пользователя (XML): ежедневно, при входе, догон пропущенного, без окна консоли; --now — первый бекап; php.path.
- scheduled / check: окно-предупреждение, если у сайта нет удачного бекапа alert_days дней; на сайте — «Последний удачный бекап» у токена.
- Настройки клиента — у каждого сайта свои (блок sites.<имя>), add записывает их явно; ping/add/list показывают корень бекапа.
- Кнопка «Скачать клиент» и ссылка на zip клиента в окне создания токена.

gtsBackup 1.0.0-beta
- Бекап файлов (полный / дифференциальный) и базы по бессрочному токену.
- Клиент gtsbackup.cmd с ротацией, проверкой и восстановлением.
