gtsBackup — бекап сайта MODX на ваш компьютер

Сайт собирает архив файлов (полный или дифференциальный) и дамп базы и отдаёт их по токену.
Клиент на компьютере забирает бекапы по HTTP или HTTPS, проверяет, хранит и сам удаляет старые.

Требования. Сайт: MODX 2.x, PHP 7.4+, пакет gtsAPI (ставится сам как зависимость).
Компьютер: Windows (или Linux/macOS), PHP 7.4+ с расширениями curl и zlib.


БЫСТРЫЙ СТАРТ — 5 минут, дальше всё само

1. Установите пакет gtsBackup на сайт.

2. Менеджер → Компоненты → Бекапы → вкладка «Токены» → «Создать токен».
   Название — чей это компьютер, например «Офис». Откроется окно:
     1) ссылка на клиент — откройте её в браузере, скачается gtsBackup-client.zip;
     2) готовая команда — скопируйте её целиком;
     3) сам токен — показывается один раз.

3. На компьютере распакуйте zip, например в C:\gtsBackup.

4. Откройте консоль (Пуск → cmd, права администратора не нужны) и выполните:

     cd /d C:\gtsBackup
     gtsbackup.cmd add <сайт> <адрес> <токен> --dest=D:\Backups --time=03:30 --now

   (это команда из окна, в конец допишите --now; папку и время поменяйте под себя).

   Команда:
     - проверит связь и токен и покажет, какая папка сайта бекапится;
     - запишет настройки этого сайта в gtsbackup.json (блок sites.<сайт>);
     - запомнит, где лежит php.exe;
     - сама поставит в Планировщик Windows задачу «gtsBackup» от вашего пользователя:
         каждый день в 03:30 и через 5 минут после входа в Windows,
         если компьютер был выключен — при первой возможности, окно консоли скрыто;
     - с --now сразу снимет первый, полный бекап.

   Если php.exe не в PATH, перед командой укажите его один раз:
     set GTSBACKUP_PHP=C:\php\php.exe

   Второй сайт: создайте токен на нём и выполните его команду add — задача уже есть
   и бекапит все сайты из настроек.

5. Проверка: gtsbackup.cmd list  и  gtsbackup.cmd check

Задача работает, пока вы вошли в Windows (как и сам компьютер для бекапов обычно включён
днём). Пропущенное — догоняется при следующем входе.


ЕСЛИ БЕКАПЫ НЕ ДЕЛАЮТСЯ

Каждый запуск задачи проверяет все сайты. Если у сайта нет удачного бекапа alert_days дней
(по умолчанию 2), на экране появляется окно «gtsBackup» со списком таких сайтов и датой
последнего удачного бекапа. Причина — в журнале <папка бекапов>\<сайт>\gtsbackup.log.
Вручную: gtsbackup.cmd check (код выхода 1, если есть пропуски или нет задачи).

На сайте: Компоненты → Бекапы → Токены, колонка «Последний удачный бекап» — по каждому
компьютеру.


ЧТО И СКОЛЬКО ХРАНИТСЯ

Бекапы хранятся цепочками. Цепочка — один полный бекап и дифференциальные от него.
Дифференциальный содержит только то, что изменилось с момента ЕГО полного, поэтому для
восстановления нужны ровно два архива: полный и выбранный дифференциальный.

  D:\Backups\<сайт>\
      20261112-033000\              цепочка, имя = время полного
          full\                     полный бекап: файлы + база
          diff-20261113-033000\     дифференциальные этого полного: изменённые файлы + база
          diff-20261114-033000\
      20261119-033000\              следующая цепочка
          full\
          ...
      gtsbackup.log                 журнал

Какой дифференциальный от какого полного — видно по папке. То же показывает gtsbackup.cmd list:
дерево цепочек, сколько хранится, что будет при следующем запуске.

Каждый запуск в режиме auto (так работает задача) решает сам:
  - полный, если полного ещё нет, ему full_every_days дней или от него уже max_diff дифференциальных;
  - иначе дифференциальный от последнего полного.

По умолчанию, при ежедневном запуске:
  full_every_days = 7   полный раз в неделю
  max_diff        = 6   между ними 6 дифференциальных
  keep_full       = 4   хранятся 4 цепочки — около 4 недель: 4 полных и до 24 дифференциальных
  keep_db_only    = 14  бекапов «только база» (если снимаете их отдельно, --no-files)

Старые цепочки удаляются целиком после каждого удачного бекапа. Неудачный бекап ничего не удаляет.
Настройки у каждого сайта свои — блок "sites" → "<сайт>" в gtsbackup.json (add записывает туда
все значения явно; их же можно задать в add: --keep-full=8 --max-diff=6 --alert-days=3 …).


КАКАЯ ПАПКА САЙТА БЕКАПИТСЯ

Корень сайта MODX — папка, где лежат index.php и config.core.php. Если core вынесен за корень,
он добавляется сам (в архиве — папка @core). Другой корень — системная настройка gtsbackup_root,
исключения — gtsbackup_exclude. Что именно бекапится, показывают gtsbackup.cmd ping и list.


ГДЕ ЧТО ЛЕЖИТ В ПАКЕТЕ

  core/components/gtsbackup/client/        клиент (то же, что в zip из админки)
      gtsbackup.cmd                        запуск в Windows
      gtsbackup.php                        сам клиент (Linux/macOS: php gtsbackup.php …)
      gtsbackup.example.json               пример настроек клиента
      protocol.md                          описание протокола обмена клиента с сайтом
  assets/components/gtsbackup/action.php   адрес, на который ходит клиент

Если сайт закрыт белым списком на веб-сервере, откройте путь /assets/components/gtsbackup/action.php.


КОМАНДЫ КЛИЕНТА

  gtsbackup.cmd list                       цепочки, сколько хранится, что дальше
  gtsbackup.cmd backup all                 снять сейчас (auto)
  gtsbackup.cmd backup <сайт> full         принудительно полный
  gtsbackup.cmd verify <сайт> <номер>      проверить архив и дамп
  gtsbackup.cmd restore <сайт> <номер> D:\restore\site
                                           развернуть в пустую папку; для дифференциального
                                           сам возьмёт его полный; дамп базы — рядом, _db.sql.gz
  gtsbackup.cmd task 03:30                 поставить/поменять время задачи
  schtasks /Run /TN gtsBackup              запустить задачу сейчас
  gtsbackup.cmd help

Номер бекапа — время его снятия, например 20261113-033000 (видно в list).


НАСТРОЙКИ САЙТА

Системные настройки, пространство gtsbackup: что бекапить и что исключать, способ дампа базы
(mysqldump или PHP, если mysqldump на сервере нет), только HTTPS, белый список IP.
Журнал бекапов — вкладка «Журнал» в разделе «Бекапы». Отключить компьютер — снять у его
токена галочку «Активен».

Linux / macOS: php gtsbackup.php add … ; расписание — cron:
  30 3 * * * php /opt/gtsbackup/gtsbackup.php backup all auto
